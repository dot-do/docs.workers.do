:::note[.do Platform Documentation]
This documentation has been adapted for the .do platform. Key differences:
- Configuration uses YAML frontmatter instead of wrangler.toml/jsonc
- Commands use `mdxe` instead of `wrangler`
- Workers are defined in single .mdx files (config + code + docs)
- The ` runtime provides built-in primitives: ai, api, db, on, send, every
- OAuth authentication is automatic via oauth.do
:::






# mdxe - Business-as-Code for Workers

**mdxe** is the zero-config development environment for .do workers. Write your worker in a single `.mdx` file that combines configuration, implementation, and documentation.

## Quick Start

### 1. Create a Worker

```sh
mdxe create my-worker.mdx
```

This creates a single file with everything you need:

```mdx
---
$type: Worker
$id: my-worker
name: my-worker
main: src/index.ts
compatibility_date: "2025-01-01"
---

# My Worker

This worker does amazing things!

\```typescript
export default {
  async fetch(request, $) {
    return Response.json({
      message: 'Hello from my-worker!',
      user: $.user?.name || 'Anonymous'
    })
  }
}
\```
```

### 2. Run Locally

```sh
mdxe run my-worker.mdx --dev
```

Open http://localhost:8787 to see your worker.

### 3. Deploy

```sh
mdxe run my-worker.mdx --deploy
```

Your worker is now live at `https://my-worker.do`!

## The .mdx Format

Every worker is a single `.mdx` file with three sections:

### 1. YAML Frontmatter (Configuration)

All worker configuration goes in the frontmatter:

```yaml
---
$type: Worker
$id: my-worker
name: my-worker
main: src/index.ts
compatibility_date: "2025-01-01"

# All standard worker configuration
observability:
  enabled: true

services:
  - binding: DB
    service: db

kv_namespaces:
  - binding: CACHE
    id: my-cache

r2_buckets:
  - binding: STORAGE
    bucket_name: my-storage
---
```

### 2. Markdown Documentation

Document your worker with standard Markdown:

```markdown
# My Worker

## Overview

This worker provides a REST API for managing tasks.

## Endpoints

- `GET /tasks` - List all tasks
- `POST /tasks` - Create a task
- `PUT /tasks/:id` - Update a task
- `DELETE /tasks/:id` - Delete a task

## Authentication

All endpoints require authentication via OAuth.
```

### 3. TypeScript Implementation

Write your worker code in `typescript` code blocks:

```mdx
\```typescript
import { Hono } from 'hono'

const app = new Hono()

app.get('/tasks', async (c) => {
  const tasks = await c.env.$.db.query({
    sql: 'SELECT * FROM tasks WHERE user_id = ?',
    params: [c.env.$.user.id]
  })

  return c.json({ tasks })
})

app.post('/tasks', async (c) => {
  const { title } = await c.req.json()

  await c.env.$.db.execute({
    sql: 'INSERT INTO tasks (title, user_id) VALUES (?, ?)',
    params: [title, c.env.$.user.id]
  })

  return c.json({ success: true })
})

export default app
\```
```

## Commands

### `mdxe create`

Create a new worker from a template:

```sh
# Basic worker
mdxe create my-worker.mdx

# From template
mdxe create my-api.mdx --template api

# Interactive prompts
mdxe create
```

**Available templates:**
- `basic` - Minimal hello world
- `api` - REST API with Hono
- `cron` - Scheduled task
- `queue` - Queue consumer
- `websocket` - WebSocket server
- `ai` - AI-powered worker
- `auth` - Authentication example

### `mdxe run`

Run or deploy a worker:

```sh
# Development mode (local)
mdxe run worker.mdx --dev

# Deploy to production
mdxe run worker.mdx --deploy

# Deploy to specific environment
mdxe run worker.mdx --deploy --env staging

# Custom port
mdxe run worker.mdx --dev --port 3000

# Watch mode (auto-reload)
mdxe run worker.mdx --dev --watch
```

### `mdxe build`

Build worker without deploying:

```sh
# Build to dist/
mdxe build worker.mdx

# Custom output directory
mdxe build worker.mdx --out ./build

# Generate traditional structure
mdxe build worker.mdx --traditional
```

Generates:

```
dist/
├── wrangler.jsonc    # Extracted from frontmatter
├── src/
│   └── index.ts      # Extracted from typescript blocks
├── README.md         # Extracted from markdown
└── package.json      # Auto-generated
```

### `mdxe test`

Test your worker:

```sh
# Run tests
mdxe test worker.mdx

# Watch mode
mdxe test worker.mdx --watch

# Coverage
mdxe test worker.mdx --coverage
```

### `mdxe login`

Authenticate with the .do platform:

```sh
mdxe login
```

Opens browser for OAuth authentication.

### `mdxe init`

Convert existing worker to .mdx format:

```sh
# From directory
mdxe init ./my-worker

# Creates my-worker.mdx from:
# - wrangler.jsonc
# - src/index.ts
# - README.md
```

## Configuration

### All wrangler.jsonc Fields Supported

```yaml
---
$type: Worker
$id: my-worker
name: my-worker
main: src/index.ts
compatibility_date: "2025-01-01"

# Observability
observability:
  enabled: true

# Service bindings (RPC)
services:
  - binding: DB
    service: db
  - binding: AUTH
    service: auth

# KV namespaces
kv_namespaces:
  - binding: CACHE
    id: my-cache

# R2 buckets
r2_buckets:
  - binding: STORAGE
    bucket_name: my-storage

# D1 databases
d1_databases:
  - binding: DB
    database_name: production
    database_id: xxx

# Queues
queues:
  consumers:
    - queue: my-queue
      max_batch_size: 10
  producers:
    - queue: my-queue
      binding: QUEUE

# Dispatch namespaces (Workers for Platforms)
dispatch_namespaces:
  - binding: do
    namespace: production

# Environment variables
vars:
  ENVIRONMENT: production
  LOG_LEVEL: info

# Routes
routes:
  - pattern: my-worker.do/*
    custom_domain: true

# Limits
limits:
  cpu_ms: 50

# Placement
placement:
  mode: smart
---
```

## Code Block Conventions

**Important:** Use the correct code block language!

```mdx
\```typescript
// This code is EXTRACTED to src/index.ts
export default {
  async fetch(request, $) {
    return new Response('Hello!')
  }
}
\```

\```ts
// This code is DOCUMENTATION ONLY (not extracted)
// Use for examples and usage snippets
const response = await fetch('https://my-worker.do')
const data = await response.json()
\```

\```bash
# Shell commands (documentation)
curl https://my-worker.do
\```
```

**Rule:** Only `typescript` blocks are extracted. All others (`ts`, `bash`, `json`, etc.) remain as documentation.

## Examples

### REST API with Database

```mdx
---
$type: Worker
$id: tasks-api
name: tasks-api
compatibility_date: "2025-01-01"
---

# Tasks API

CRUD API for managing tasks.

\```typescript
import { Hono } from 'hono'

const app = new Hono<{ Bindings: { $: RuntimeContext } }>()

// List tasks
app.get('/tasks', async (c) => {
  const tasks = await c.env.$.db.query({
    sql: 'SELECT * FROM tasks WHERE user_id = ? ORDER BY created_at DESC',
    params: [c.env.$.user.id]
  })

  return c.json({ tasks })
})

// Create task
app.post('/tasks', async (c) => {
  const { title, description } = await c.req.json()

  await c.env.$.db.execute({
    sql: 'INSERT INTO tasks (title, description, user_id) VALUES (?, ?, ?)',
    params: [title, description, c.env.$.user.id]
  })

  return c.json({ success: true })
})

// Update task
app.put('/tasks/:id', async (c) => {
  const id = c.req.param('id')
  const { title, description, completed } = await c.req.json()

  await c.env.$.db.execute({
    sql: `UPDATE tasks
          SET title = ?, description = ?, completed = ?
          WHERE id = ? AND user_id = ?`,
    params: [title, description, completed, id, c.env.$.user.id]
  })

  return c.json({ success: true })
})

// Delete task
app.delete('/tasks/:id', async (c) => {
  const id = c.req.param('id')

  await c.env.$.db.execute({
    sql: 'DELETE FROM tasks WHERE id = ? AND user_id = ?',
    params: [id, c.env.$.user.id]
  })

  return c.json({ success: true })
})

export default app
\```
```

### AI-Powered Worker

```mdx
---
$type: Worker
$id: ai-assistant
name: ai-assistant
compatibility_date: "2025-01-01"
---

# AI Assistant

Chat with an AI assistant.

\```typescript
export default {
  async fetch(request, $) {
    if (request.method !== 'POST') {
      return new Response('Method not allowed', { status: 405 })
    }

    const { message } = await request.json()

    // Generate AI response
    const response = await $.ai.chat({
      messages: [
        { role: 'system', content: 'You are a helpful assistant.' },
        { role: 'user', content: message }
      ],
      model: 'claude-3-5-sonnet-20241022'
    })

    // Store conversation
    await $.db.execute({
      sql: `INSERT INTO conversations (user_id, message, response)
            VALUES (?, ?, ?)`,
      params: [$.user.id, message, response.content]
    })

    return Response.json({ response: response.content })
  }
}
\```
```

### Scheduled Task

```mdx
---
$type: Worker
$id: daily-digest
name: daily-digest
compatibility_date: "2025-01-01"
---

# Daily Digest

Send daily email digest to users.

\```typescript
export default {
  async scheduled(event, $) {
    // Get all active users
    const users = await $.db.query({
      sql: 'SELECT * FROM users WHERE email_notifications = true'
    })

    // Generate and send digest for each user
    for (const user of users) {
      // Get user's recent activity
      const activities = await $.db.query({
        sql: `SELECT * FROM activities
              WHERE user_id = ? AND created_at > NOW() - INTERVAL '1 day'
              ORDER BY created_at DESC`,
        params: [user.id]
      })

      // Generate personalized digest
      const digest = await $.ai.generateText({
        prompt: `Create a personalized daily digest for ${user.name} based on these activities: ${JSON.stringify(activities)}`,
        model: 'claude-3-5-sonnet-20241022'
      })

      // Send email
      await $.send.email({
        to: user.email,
        subject: 'Your Daily Digest',
        html: digest
      })
    }

    return new Response('Digest sent!')
  }
}
\```
```

## Best Practices

Keep everything in one file:

```mdx
---
# Configuration
$type: Worker
$id: my-worker
name: my-worker
---

# Documentation
Complete docs here...

\```typescript

\```
```

### 2. Document as You Code

```mdx
## API Endpoints

### GET /users

Returns list of users.

**Query Parameters:**
- `page` - Page number (default: 1)
- `limit` - Results per page (default: 20)

**Response:**
\```json
{
  "users": [...],
  "total": 100,
  "page": 1
}
\```

\```typescript
app.get('/users', async (c) => {
  const page = parseInt(c.req.query('page') || '1')
  const limit = parseInt(c.req.query('limit') || '20')

})
\```
```

## Comparison

| Feature | Traditional | mdxe (.mdx) |
|---------|------------|-------------|
| Files | 5+ files | 1 file |
| Config | wrangler.toml | YAML frontmatter |
| Code | src/ directory | `typescript` blocks |
| Docs | README.md | Markdown sections |
| Setup | npm install, configure | Zero config |
| Deploy | wrangler deploy | mdxe run --deploy |
| Dev | wrangler dev | mdxe run --dev |

## Migration from Traditional Workers

Convert existing workers to .mdx format:

```sh
# From existing project
cd my-worker
mdxe init .

# Generates my-worker.mdx from:
# - wrangler.jsonc → YAML frontmatter
# - src/index.ts → typescript block
# - README.md → Markdown section
```
